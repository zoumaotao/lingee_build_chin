02 MCP APPS 平台能力（6项）

#1APPS 不支持租户级自定义开发与发布上架 ❌ 未解决
当前现状
仅标品预置组件，不支持自定义
标品应有能力
支持开发者自定义 APPS 组件并发布到租户
为什么是标品问题
每个企业交互需求不同，不开放自定义则能力天花板极低
#2APPS 与 LLM 数据传递仅支持全量消息，缺乏上下文精简机制 ❌ 未解决
当前现状
用户选 100 条数据必须全量塞入对话
标品应有能力
对话展示精简提示，实际数据静默更新 LLM 上下文
为什么是标品问题
Token 浪费 + 对话不可读 + 模型性能下降
#3APPS 组件渲染性能差，偶发渲染失败 ❌ 未解决
当前现状
滚动后组件被释放，回来重新渲染慢 / 偶发白屏
标品应有能力
合理缓存 + 状态恢复
为什么是标品问题
回看上文是高频操作
#4APPS 组件提交后不支持内容回显 ❌ 未解决
当前现状
提交后回看对话，已填内容消失
标品应有能力
数据持久化，回看可回显
为什么是标品问题
表单提交 → 回看是基本闭环
#5APPS 支持获取灵基登录用户信息 ✅ 已解决
当前现状
此前无法获取用户身份
标品应有能力
可获取用户 ID / 姓名 / 邮箱 / 部门
为什么是标品问题
几乎所有企业场景需要身份
#6Agent 无法感知 MCP APP 组件的内部业务逻辑 ❌ 未解决
当前现状
Agent 仅知道入参出参和名称描述
标品应有能力
结构化组件能力描述（JSON Schema）
为什么是标品问题
限制 AI 辅助开发上限

多区域部署（新加坡）

#8DC 不支持第三方系统写入知识 ❌ 未解决

无写入 API

当前现状
可检索到不属于自己权限的内容
标品应有能力
严格权限控制
为什么是标品问题
企业级基本安全要求

04 部署与身份体系（2项）

#10Build 开发的应用仅支持部署到苍穹 ❌ 未解决
当前现状
只能托管苍穹，苍穹有许可体系，灵基用户无苍穹账号
标品应有能力
支持多种部署目标（苍穹 / 灵基自身 / 客户云服务器），身份基于灵基用户体系
为什么是标品问题
灵基适用场景不应限于 ERP 用户圈
#11应用开发要求过多不相关文件权限 ❌ 未解决
当前现状
大量不相关权限请求
标品应有能力
最小权限原则
为什么是标品问题
违反安全原则，企业客户会触发审批

06 开发范式与工具链（12项）

#28端到端开发流程完全断裂（最关键问题） ❌ 未解决
⚠️ 这是灵基 Build 走向生产级平台最根本的问题。
当前开发者需在 5+ 个工具 / 环境间反复切换，各环节零衔接。

当前碎片化流程

产品设计 (Kiro) → MCP APPS (本地IDE→KDM) → Skill (Build→Console→Work) → 智能体 (Build→Console→Work) → 应用 (本地苍穹→Build→苍穹上线→配MCP) → 联调 (Work)
标品应有能力
终态：一站式工作空间
初阶：各环节自动化衔接
为什么是标品问题
Build 从"演示工具"走向"生产级开发平台"的根本问题
#16测试智能体必须先将技能上线 ❌ 未解决

违反开发 → 测试 → 上线基本流程

#17构建同名 Skill 点击测试会静默覆盖线上 Skill ❌ 未解决

缺乏同名冲突处理机制，应沙箱隔离 + 上线时提醒

#18智能体 MCP Server 关联与知识挂载无法在 Build 中连贯完成 ❌ 未解决

需在 Build / Console / Work 三处切换，角色职责混淆

#19智能体没有版本管理 ❌ 未解决

无法查看历史 / 对比 / 回滚

#20智能体实例创建对苍穹有不明确依赖 ❌ 未解决

需澄清是否合理，与 #10 同一架构耦合问题

#21智能体创建 Skill 后缺乏同步批量发布机制 ❌ 未解决

需手动按顺序逐个发布

#22Build 中更换 Agent 的 Skill 后工作区未同步 ❌ 未解决

对话操作不反映到实际文件

#23技能在智能体中被修改后无法同步上线 ❌ 未解决

需手动复制回源文件再单独提交

#24智能体 / 技能文件修改后文件树无状态标记 ❌ 未解决

无法识别哪些已修改 / 未提交

#25提交同名技能因名称重复失败 ❌ 未解决

修改后重新提交被当作新建

#26Build 使用 fast 模型时进入死循环 ❌ 未解决
#27Build 使用 deep 模型时回复无限加载 ❌ 未解决
