# 灵基交互需求设计

> 适用范围：灵基 Work 平台上的 HelpDesk 交互能力  
> 更新日期：2026-08-13  
> 依赖文档：振兴 Helpdesk 需求清单（开发版 0813）  
> 状态：设计中

---

## 一、工单状态定义（4 状态）

| 状态 | 说明 | 进入条件 |
|------|------|---------|
| 新建 | 刚创建，AI 路由中 | 用户或 AI 创建工单 |
| 待分配 | 已识别处理组，未指定处理人 | 路由到组但未匹配到人、Agent 修改分类后 |
| 处理中 | 已指定处理人，双方沟通中 | 自动分配、Manager 分配、转派、员工驳回 |
| 已关闭 | 员工确认解决 | 员工执行"已解决" |

```
新建 → 待分配 → 处理中 → 已关闭（员工确认）
                  ↑         ↓ (员工驳回)
                  |_________|
```

**核心规则**：
- 处理人只管**答复**，不操作状态
- **员工决定是否解决**：看到答复后点"已解决"关闭工单，或"驳回"回到处理中
- 回复不改变状态；转派不改变状态
- 没有"提交已解决""待提交人确认"中间状态

## 二、灵基 Work 应用菜单

Work 左侧菜单下挂载工单后台应用页面：

### 2.1 我的工单（员工视角）

**视图**：全部 / 处理中 / 待评价 / 已关闭

**页面能力**：工单列表、详情页（时间线+回复记录+附件）、确认解决/驳回、新建工单入口、统计摘要

### 2.2 我的任务（处理人视角）

**视图**：全部 / 处理中 / 待评价 / 已关闭

**页面能力**：工单列表（SLA 超时高亮）、详情页、答复、修改分类/优先级、统计摘要

### 2.3 运营仪表盘（Manager 视角）

**页面能力**：按业务处理组/处理人/公司/分类筛选、工单量/SLA/满意度指标、待分配队列、团队负载

### 2.4 通知方式

第一期只用邮件通知，覆盖：创建、分配、转派、回复、驳回、关闭、SLA 预警、休假自动回复。Work 页面实时查询后台展示最新状态。

## 三、员工智能体交互（4 张卡片）

### 3.1 卡片清单

| # | 卡片 | 组件 | 什么时候用 |
|---|------|------|-----------|
| 1 | 知识检索卡 | employee/resolution | 员工提问，智能体从知识库找到方案 |
| 2 | 工单草稿卡 | employee/ticket-draft | 知识没解决，AI 生成草稿让员工确认 |
| 3 | 工单列表卡 | employee/ticket-list | 员工查看自己的工单列表（含统计） |
| 4 | 工单详情卡 | employee/ticket-detail | 一切工单相关展示（数据驱动） |

### 3.2 流程

```
员工提问
  ↓
① 知识检索卡 → 已解决？→ 结束
                → 仍未解决 ↓
② 工单草稿卡（AI 填充一级分类+优先级，附件勾选）→ 确认提交
  ↓
④ 工单详情卡（刚创建：工单号+团队+待分配）
  ↓
  员工查进度 → ③ 列表卡 → 点某张 → ④ 详情卡
  或直接说"看下那个工单" → ④ 详情卡
  ↓
  有答复时显示"已解决 / 驳回"
  ↓
  已解决 → 卡片内切换为评分 → 提交评价 → 闭环
  驳回 → 卡片内切换为原因输入 → 提交驳回 → 回到处理中
```

### 3.3 工单详情卡设计（数据驱动）

后台返回什么字段就展示什么：

| 数据 | 展示 |
|------|------|
| ticketId / title / status | 工单号 + 标题 + 状态 badge |
| requester | 提单人信息 |
| description | 问题描述 |
| assignee / team | 处理人 + 团队（无则"待分配"） |
| sla | SLA 时限 |
| attachments | 附件列表 |
| 沟通记录（所有答复往来） | 按时间线展示 |
| timeline | 处理轨迹（有答复时折叠） |

**按钮**：
- 无答复时：查看详情
- 有答复时：**已解决** / **驳回**
- 点已解决 → 评分（必须打分）
- 点驳回 → 填原因 → 提交

**自然语言直接操作**：用户说"已解决我来评价" → 智能体调 Close_Ticket → 直接展示评分步骤。

## 四、处理人智能体交互（2 张卡片）

### 4.1 卡片清单

| # | 卡片 | 组件 | 什么时候用 |
|---|------|------|-----------|
| 1 | 工单列表卡 | agent/queue | 查看待处理工单（含统计） |
| 2 | 工单详情卡 | agent/ticket-detail | 查看工单 + 答复（一张卡贯穿） |

### 4.2 流程

```
处理人："看看我的待办"
  ↓
① 工单列表卡（按 SLA 排序，超时高亮，含统计）
  ↓
点某张 / "看下这张工单"
  ↓
② 工单详情卡：
  - 看到：提单人、描述、沟通记录、处理轨迹
  - 可改：一级分类、优先级
  - 答复区默认展开 → 输入内容 → 保存草稿 / 发送答复
  ↓
"帮我总结生成知识" → 智能体生成产物文件 → 右侧面板"上传智能体知识"（平台承接）
```

### 4.3 工单详情卡设计

**展示内容**：
- 工单标题 + 工单号 + SLA
- 提单人信息（姓名/部门/邮箱）
- 问题描述
- 沟通记录（双方所有往来回复，按时间线）
- 处理轨迹（折叠）
- 一级分类（下拉，可修改，23 个选项）
- 优先级（下拉，可修改）

**答复区（默认展开）**：
- 答复内容输入框
- 附件（折叠，从对话上下文拉取，默认不勾选，用户自己选）
- 内部备注（折叠，提单人不可见）
- 按钮：**保存草稿**（存到工单后台） / **发送答复**

**处理人只做一件事：答复**。不操作状态，不转派（转派通过后台"我的任务"页面做）。

## 五、知识产物（平台承接）

处理人让智能体"帮我总结这个工单的解决方法"：
1. 智能体根据工单处理记录生成产物文件
2. 产物出现在灵基 Work 右侧面板
3. 处理人悬停产物图标，点击"上传智能体知识"
4. 知识写入 Console 知识管理 + 同步至对应智能体知识库

**约束**：仅有 Console"知识管理"权限的用户可见上传按钮；非智能体产物灰显；携带来源智能体 ID；同名去重。

## 七、交互规则

1. **fail closed**：写操作必须收到后台成功回执才显示成功
2. **身份不可篡改**：employeeId 仅来自平台
3. **回复不改状态**：处理人答复后工单仍为处理中
4. **关闭由员工操作**：处理人不操作状态
5. **附件默认不勾选**：从对话上下文拉取，用户自己决定带哪些
6. **自然语言+卡片双通道**：用户可以直接说"已解决"而不必点按钮
7. **AI 只识别一级分类（23 个）**：二级分类由 Agent 补充
8. **草稿保存到工单后台**：处理人在智能体对话里保存的答复草稿存到后台

## 八、与工单后台的关系

| 职责 | 归属 |
|------|------|
| 工单 CRUD、状态流转、分类、SLA、邮件通知、看板 | 工单后台 |
| AI 识别分类/优先级、对话、知识检索 | 灵基平台（Skill + DC） |
| 业务组件渲染（卡片） | 灵基平台（MCP Apps） |
| Work 菜单页面（我的工单/我的任务/仪表盘） | 工单后台应用嵌入 Work |
| 知识产物上传 | 灵基 Work 平台 |

**闭环**：工单后台负责状态和业务逻辑，Work 页面负责展示和操作入口，智能体负责对话式交互和卡片呈现。
