# 智能体知识飞轮需求规格

> 需求提出：邹茂桃、彭卫华、陆阳
> 形成日期：2026-08-12
> 适用范围：灵基 Work / Build、智能体详情、MCP Apps、HelpDesk、企业级 DC 知识平台
> 状态：Foundation 最新反馈已明确能力边界：**对话过程仅支持加工后的知识产物写入 DC；对话附件不能直接写入 DC**。未加工原文件如需入库，应由有权限用户在智能体详情或 DC 管理界面直接上传；对话处理会消耗点数，不应用于单纯搬运原文件。相关链路仍需联调/UAT。

## 1. 背景与需求结论

### 1.1 已确认的 Foundation / DC 能力基线（最新反馈）

Foundation 最新反馈明确：

1. 对话链路只能将**对话过程中生成的加工产物**写入企业知识（DC）。
2. 对话中的 PDF、图片、压缩包等附件不能作为文件随产物直接写入 DC。
3. 未加工原文件如确需作为知识源，应由有权限用户在智能体详情或 DC 管理界面点击上传；该路径更经济，可避免为文件搬运消耗对话点数。
4. HelpDesk 工单附件默认不上传原件。AI 可通过受控附件 URL 理解内容并生成脱敏摘要，摘要作为对话知识产物的一部分进入 DC。

该能力可承接振兴 HelpDesk **“工单处理 → 生成知识产物 → 用户确认 → 写入 DC”** 的基础闭环，但需明确：

- “对话产物”必须是经过模型整理、摘要、结构化或人工编辑确认的内容，不等同于原始附件。
- 对话上传会消耗点数，不应为了把原文件从一处搬到另一处而调用；原文件优先走现有界面上传。
- 原文件界面上传仍需执行 DC 自身的文件安全、权限、解析、索引和发布流程。
- “产物已生成”不等于已写入 DC；只有真实 DC 回执及知识标识才能表示入库成功。
- 标准产物写入不自动解决智能体主动发现候选、冲突去重、审核运营和效果回流等高级知识飞轮能力。

### 1.2 知识飞轮扩展需求

智能体详情/DC 管理界面已支持运营人员通过“新增知识”手工上传文件并发布。本需求在 Foundation 最新边界下定义两类入口：

1. **对话知识产物沉淀**：用户在会话中引用当前对话或工单，要求智能体整理为知识；智能体生成加工后的知识产物并提交 DC。对话附件本身不进入 DC。
2. **智能体内驱动**：智能体在服务过程中识别高频问题、已验证解决方案、低命中知识、重复工单或高质量处理总结，主动生成知识候选并邀请有权限的人审核。

原始文件是独立入口：用户在智能体详情或 DC 管理界面直接上传，不经对话搬运。三类入口（界面文件上传、对话产物、智能体内驱候选）必须复用同一条企业级 DC 治理链路，不能形成三套知识库或绕开权限、审核与审计。该能力属于知识飞轮实践：**知识消费 → 服务执行 → 结果验证/反馈 → 候选提炼 → 治理发布 → 再次消费 → 效果度量与持续优化**。

### 1.3 与最新 HelpDesk 交付计划的关系

- 员工 Skill 目标 8/14；处理人 Skill 目标 8/17。
- 处理人 Skill 的范围包含“生成知识产物”。HelpDesk 当前采用**定时任务发现候选 + 对话生成知识产物**：定时读取符合条件的已完成工单，用户在处理人对话中检查并形成加工产物，再调用 Foundation 产物写入能力；后台任务输出不能直接写入 DC。
- 知识产物卡负责展示、编辑、确认和反馈；它不能把对话附件或后台文件引用伪装为可入库产物，也不能替代 DC 真实回执。
- 工单草稿卡和附件确认卡仍可为“创建/补充工单”使用会话附件，但该附件能力与“附件写入 DC”无关。知识沉淀时，工单附件仅供 AI 通过 HelpDesk 受控 URL 理解并生成摘要，原文件不经对话入 DC。
- 需要产品确认 eligible ticket：至少考虑已解决/已确认、处理结论完整、附件摘要可用范围、PII/敏感信息、重复知识和人工确认。

## 2. 目标与非目标

### 2.1 目标

- 用户在对话中把已确认的工单解决方案、对话结论和附件脱敏摘要整理为知识产物，并以真实 DC 回执完成入库；对话附件本身不进入 DC。
- 用户如需把 PDF、图片等原始文件作为知识源，应在智能体详情或 DC 管理界面直接上传，避免为文件搬运消耗对话点数。
- 智能体可基于可解释规则主动发现知识候选，但默认不能无审核直接发布。
- 写入企业级 DC 后与租户、智能体、实例、来源、权限、版本和审核记录完整关联。
- 写入结果必须明确返回成功、处理中或失败；不得把“已生成草稿”表述为“已写入 DC”。
- 所有知识均可追溯、可更新、可撤回、可审计，并可用实际命中与解决反馈评估价值。

### 2.2 非目标

- 不允许通过对话把附件原文件直接写入 DC，也不为绕过该限制而把二进制、Base64 或临时 URL 包装成“知识产物”。
- HelpDesk 工单原始附件默认不上传至 DC；智能体仅可通过有权限、有有效期、可审计的附件 URL 读取内容，完成敏感信息检查后生成摘要，并将摘要作为知识产物的一部分。
- 不允许普通用户绕过知识管理员将内容直接公开给全企业。
- 不以本地原型或 MCP Apps 卡片代替 DC 的持久化、索引和权限服务。
- 本期不解决 SharePoint 等外部数据源主动同步；该能力仍归属 DC 连接器（问题 #8c）。

## 3. 用户与权限

| 角色 | 可发起 | 可编辑草稿 | 可审核/发布 | 可撤回 | 默认范围 |
|---|---|---|---|---|---|
| 普通员工 | 对话提出知识产物建议 | 仅本人草稿 | 否 | 本人未提交草稿 | 继承当前会话可见范围 |
| 工单处理人 | 工单转知识、对话提交 | 是 | 按授权 | 按授权 | 所属业务线/处理组 |
| 智能体 | 自动生成候选 | 仅生成结构化候选 | 默认否 | 否 | 继承来源与目标智能体 |
| 知识审核员 | 查看待审 | 是 | 是 | 是 | 授权知识域 |
| 智能体管理员 | 手工上传、配置策略 | 是 | 按策略 | 是 | 指定智能体/实例 |
| 租户管理员 | 配置全局策略 | 是 | 是 | 是 | 本租户 |

强制规则：调用方必须具备 `knowledge:create`；有关联智能体时还必须具备目标智能体贡献权限，发布还需 `knowledge:publish`。无智能体时只能写入当前租户允许的企业知识空间并标记 `unbound`，不得猜测或静默绑定智能体。跨租户禁止，跨智能体写入需显式确认；知识可见范围不得高于来源材料允许的范围。

## 4. 三类入库路径与关键交互

### 4.0 对话知识产物写入（Foundation 最新能力）

适用于对话过程中生成并经用户确认的加工内容，例如问题摘要、解决步骤、FAQ、操作说明和工单附件脱敏摘要：

1. 智能体根据当前对话、工单事实和允许读取的证据生成结构化知识产物。
2. 写入确认卡只展示产物文本、来源引用、目标知识域、权限和风险，不把对话附件列为待上传文件。
3. 用户确认后调用 Foundation / DC 产物写入能力；只有真实回执返回知识标识和状态，才能显示已接收、处理中或成功。
4. 对话中的 PDF、图片、压缩包等附件不得随产物写入 DC；平台应在提交前阻断并提示“请到智能体详情或 DC 管理界面上传原文件”。
5. 对话处理会消耗点数，因此不得使用对话链路完成单纯文件搬运。
6. 写入后仍需验证权限、解析/索引状态和授权检索；产物已生成不代表已入库。

### 4.1 智能体详情 / DC 界面手工上传原文件（现有能力保留）

运营人员在智能体详情或 DC 管理界面点击“新增知识”，选择原始文件并保存发布。该路径用于 PDF、图片、DOCX、压缩包等未加工文件，比通过对话搬运更经济，可避免不必要的对话点数消耗；仍需补充目标知识域、可见范围、文件安全、重复检测、审核策略和来源标记 `manual_agent_detail`。

### 4.2 自然语言生成知识产物（新增）

典型指令：`@HelpDesk Assistant 将当前工单的已确认解决方案整理成知识产物`。用户可以引用当前对话或工单，但不能要求把会话附件原文件直接写入 DC。

交互步骤：

1. 识别 `knowledge.artifact.create` 意图，读取当前会话文本、工单事实和允许访问的证据引用。
2. 若存在附件，只允许 AI 在授权范围内理解其内容并提取摘要；附件文件本身不进入待写入载荷。
3. 生成标题、摘要、问答/步骤、标签、来源引用及候选权限，展示知识产物确认卡。
4. 确认卡明确提示对话会消耗点数，并区分“产物内容”和“原始附件”；原始文件如需入库，提供前往智能体详情/DC 管理界面的指引。
5. 用户确认后创建知识草稿或写入任务，默认不自动发布。
6. DC 返回 `knowledgeId`、`version`、`status`、目标、范围和审计号后，按真实状态展示结果。
7. 失败时保留产物草稿；不得降级为上传附件，也不得把附件 URL、Base64 或二进制写入知识正文。

### 4.3 智能体内驱沉淀（新增）

候选触发信号至少包括：

- 相同/相似问题在 30 天内达到租户配置阈值；
- 工单已由用户确认解决，处理步骤完整且评分达到阈值；
- 知识检索无命中或低置信度，但人工处理形成稳定答案；
- 已有知识反复被反馈“未解决”，新方案经多次验证；
- 业务规则或标准操作在会话中被授权人员明确确认。

内驱流程只能自动生成候选并计算质量分，默认进入人工审核。仅当租户开启白名单、来源可信、无敏感信息、无冲突、质量分达标且权限范围明确时，才允许策略化自动发布；自动发布必须可回滚并通知知识管理员。

### 4.4 HelpDesk 定时发现 + 对话产物沉淀基线（本期采用）

1. 定时任务按配置周期读取符合条件的已完成工单；读取范围必须同时满足租户、处理组和工单数据权限。
2. 后台任务只生成待处理候选及来源引用，不能把候选、附件或文件 URL 直接写入 DC。
3. 处理人在 Agent 对话中打开候选，智能体基于工单事实生成结构化知识产物；用户检查并按需编辑后，显式确认写入 DC。
4. 工单附件不经对话上传。智能体使用受控附件 URL 读取内容并生成摘要，仅将经过敏感信息检查和脱敏的摘要纳入知识产物。
5. 附件 URL 必须绑定调用身份或短期访问凭证、设置有效期并记录访问审计；访问失败、格式不支持、内容风险过高或摘要质量不足时，阻断该摘要进入知识产物并展示原因。
6. 若业务明确要求把原始附件作为知识源，由有权限用户在智能体详情或 DC 管理界面单独上传；不得在对话中重试附件入库，也不得为文件搬运消耗点数。
7. 知识产物保留工单和附件的可追溯引用，但 DC 中知识的可见范围不得高于来源工单与附件的权限范围。

当前基线不等于自动发布：定时任务只负责发现候选，对话只负责生成并确认加工产物，DC 负责真实写入与状态回执；原始文件始终走界面上传路径。

## 5. 统一状态机

标准一键上传基础状态：

`selected → validating → uploading → accepted/processing → indexed | upload_failed | partially_succeeded`

知识飞轮受治理状态：

`detected → validating → parsing → draft → conflict_check → pending_review → approved → writing → published`

异常/分支状态：`needs_clarification`、`rejected`、`write_failed`、`partially_succeeded`、`withdrawn`、`superseded`。

- `draft` 只代表内容已生成，不代表 DC 已写入。
- 只有 DC 返回明确 `published + knowledgeId + version` 才能向用户显示“知识已发布”。
- 超时或结果未知必须显示“状态待确认”，并通过幂等键查询，禁止重复创建。

## 6. 内容治理规则

1. **解析**：压缩包先列目录再展开；禁止可执行文件、路径穿越、嵌套压缩炸弹；单文件与总大小由租户策略限制。
2. **脱敏**：识别姓名、电话、邮箱、账号、密钥、Token、客户数据、日志中的身份信息；高风险内容阻断发布。
3. **事实与引用**：保留原文件标识、会话消息、工单及解决确认的不可变证据引用；生成内容需能回溯证据片段。引用只保存标识、权限与审计关系，不包含原始附件二进制、Base64、可下载文件载荷，也不代表附件已写入 DC。
4. **冲突与去重**：按内容指纹保证请求幂等；按语义相似度识别已有知识，支持新建、合并、更新已有版本或放弃。
5. **质量**：至少校验准确性、完整性、可复用性、时效、可执行性、语言和适用范围。
6. **权限**：入库权限标签取“目标策略”与“来源 ACL”的更严格交集；检索必须按用户身份 pre-filter。
7. **生命周期**：支持草稿、审核、发布、过期复核、撤回、归档和版本回滚；来源失效时触发复核。
8. **人工可控**：展示模型提取结果与风险，不隐藏改写；发布前允许编辑，关键字段变化后旧确认失效。

## 8. 平台接口与职责边界

| 能力 | 责任方 | 最低要求 |
|---|---|---|
| 对话知识产物生成 | 灵基 Agent/Skill | 读取会话文本、工单事实和允许访问的证据，生成加工后的结构化产物；不得把附件文件放入写入载荷 |
| 原始文件界面上传 | 智能体详情 / DC Console | 由有权限用户点击上传未加工文件；执行文件安全、权限、解析和索引，不经过对话点数链路 |
| 确认/审核卡 | MCP Apps | 展示产物文本、风险和目标；明确附件不会随产物入库；收集显式确认，不自行持久化知识 |
| 对话产物写入与归属解析 | Foundation / DC | 只接收加工后的对话产物；返回真实知识标识、归属和状态；拒绝对话附件文件写入 |
| 游离企业知识管理 | DC / Console | 查看、检索前治理、后续关联智能体、调整权限、撤回与归档 |
| 统一写入、解析、索引、版本 | 企业级 DC | 标准 API、幂等、异步任务、去重、版本、回滚、状态查询 |
| 身份与权限 | 灵基 IAM + DC | 调用权限、来源 ACL、目标范围及检索权限闭环 |
| 工单事实、定时任务与反馈 | HelpDesk 后台 + HelpDesk 智能体 | 按权限定时提供符合条件的已完成工单，生成待人工处理的知识产物；不直接绕过用户确认和 DC 发布 |
| 工单附件受控读取 | HelpDesk 后台 | 提供有权限、有有效期、可审计的附件 URL；AI 读取后生成脱敏摘要，原始附件不得直接上传 DC |
| 审计与运营 | DC / Console | 全链路审计、待审列表、失败重试、撤回、指标报表 |

建议 Tool 契约：`Create_Knowledge_Ingestion`、`Parse_Knowledge_Source`、`Check_Knowledge_Conflict`、`Submit_Knowledge_Review`、`Publish_Knowledge`、`Get_Knowledge_Ingestion_Status`、`Withdraw_Knowledge`。

## 9. 验收场景

1. 在 Agent 对话中生成并确认知识产物，DC 返回真实 `knowledgeId`、归属和处理/索引状态；产物不包含附件文件载荷。
2. 对话中存在 PDF、图片或压缩包时，系统明确阻断附件直接写入 DC，并提示前往智能体详情/DC 管理界面上传原文件；阻断过程不发起无效 DC 文件写入。
3. 有权限用户通过界面直接上传原文件，文件安全、权限、解析、索引和授权检索通过；该路径不经过对话文件搬运。
4. HelpDesk 工单附件通过受控 URL 被 AI 理解并生成脱敏摘要，摘要可进入知识产物，DC 中不存在该原始附件副本。
5. 界面清楚提示对话处理会消耗点数，原文件优先直接上传；不得宣称未经确认的免费额度或具体点数价格。
6. 引用当前工单时，草稿包含工单号、解决确认和证据引用，且移除个人信息。
7. 存在 90% 相似知识时展示对比，允许更新已有版本而不是重复创建。
8. 审核拒绝后保留原因；修改后可重新提交，审计链连续。
9. DC 写入成功返回知识编号、版本、归属和索引状态；失败或超时不展示成功，重试不产生重复知识。
10. 知识仅对授权部门可检索，其他用户无法通过关键词或向量检索越权获取。
11. 智能体内驱候选能解释触发原因、证据和质量分；未配置自动发布时不会自行发布。
12. 发布后的知识被引用回答，并将“已解决/未解决”、人工升级和评分回流到效果指标。
13. 知识撤回或来源失效后检索及时下线，历史版本和审计仍可追溯。
14. 定时任务只读取当前租户和授权处理范围内符合条件的已完成工单；重复扫描同一版本工单不会生成重复知识产物。
15. 定时任务生成的只是待处理候选；候选在 Agent 对话中形成并确认知识产物前不得写入 DC，确认后按真实 DC 回执展示处理中、成功或失败。
16. 工单附件通过受控 URL 被 AI 读取并生成摘要，URL 过期、越权、格式不支持或识别出高风险敏感信息时安全失败；DC 中不存在该原始附件副本。

## 10. 指标

- 漏斗：候选数 → 草稿数 → 提审数 → 通过数 → 发布数。
- 效率：平均解析时长、平均审核时长、发布成功率、失败重试率。
- 质量：重复率、敏感信息拦截率、过期率、撤回率、审核通过率。
- 业务：知识命中率、自助解决率、转人工率、同类工单下降率、知识辅助解决时长。
- 内驱：候选采纳率、自动发布回滚率、候选到首次命中的周期。

指标必须按租户、智能体、知识域、来源和版本分层统计，不得仅统计“上传成功”。

## 11. 分阶段计划与依赖

### Foundation / DC 最新能力边界与验收

- 责任：Foundation + DC 由 @武晨曦、@陆阳明确标准能力；@邹茂桃负责 HelpDesk 场景、依赖协调与验收。
- 对话路径：只支持加工后的对话知识产物写入 DC；对话附件不能直接写入。
- 文件路径：原始文件由有权限用户在智能体详情或 DC 管理界面直接上传，避免为文件搬运消耗对话点数。
- HelpDesk 衔接：定时任务发现候选 → Agent 对话生成/确认知识产物 → Foundation 写入 DC；工单原始附件只用于生成脱敏摘要，不随产物入库。
- 验收：产物真实回执、归属、权限、幂等、审核、索引/检索；附件阻断提示；界面文件上传的安全、解析和权限；点数提示与失败处理。
- 状态：最新边界已确认，具体环境、接口和 UAT 证据仍需补齐；不得继续表述为“产物/附件均可通过对话一键上传”。

### Phase 0：高级飞轮契约与治理（与标准能力验收并行）

- 输出：自然语言/工单引用、候选生成、权限矩阵、审核策略、容量限制、效果回流和正式排期。

### Phase 1：对话式受控沉淀 MVP（DC API 就绪后 2～3 周）

- 支持会话文本、工单引用和附件脱敏摘要生成知识产物；PDF/DOCX/ZIP 等原文件不经对话写入，统一引导至智能体详情/DC 界面上传。
- 只支持“生成草稿 → 人工审核 → DC 发布”，不启用自动发布。
- 打通回执、失败重试、版本、来源追溯和基本权限。

### Phase 2：智能体内驱候选（Phase 1 后 2～4 周）

- 增加频次、解决确认、评分和低命中触发器；提供候选队列和质量分。
- 增加更新已有知识、过期复核、反馈回流及运营指标。

### Phase 3：策略化自动发布与企业连接器

- 仅对白名单知识域启用，配套回滚、抽检、告警和漂移监控。
- 与 SharePoint 等连接器统一进入 DC 治理，不另建旁路。

对话产物写入前置条件：Foundation / DC 产物接口可用、稳定身份与归属规则、权限和真实状态回执，以及对对话附件的明确阻断。原始文件界面上传另依赖智能体详情/DC 管理入口、文件安全、解析和授权检索。高级飞轮依赖工单/会话证据引用、知识权限模型、审核工作台、智能体/实例稳定标识、审计、幂等和效果回流。任一关键依赖未就绪时，只能展示候选或草稿，不能宣称形成生产知识飞轮。
