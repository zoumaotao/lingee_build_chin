# 智能体知识飞轮需求规格

> 需求提出：邹茂桃、彭卫华、陆阳
> 形成日期：2026-08-12
> 适用范围：灵基 Work / Build、智能体详情、MCP Apps、HelpDesk、企业级 DC 知识平台
> 状态：Foundation + DC 联合目标为 **2026-08-21** 发布智能体产物/附件写入 DC（`PLANNED`，尚未上线/UAT）；高级知识飞轮仍在需求与治理细化中，是否纳入 HelpDesk 2026-08-31 试运行以发布后验收为准

## 1. 背景与需求结论

### 1.1 已确认的标准能力基线（2026-08-12 更新）

经沟通最终确认，Foundation + DC 联合支持以下标准能力，由 @武晨曦、@陆阳推进，计划 **2026-08-21** 发布：

1. 处理产物和附件可一键上传为企业知识（DC）。
2. 发起上传时存在智能体上下文，则知识自动进入/关联该智能体知识。
3. 无智能体上下文时，知识仍进入当前租户企业知识池，但保持“游离”（未关联具体智能体）。

该能力可承接振兴 HelpDesk **“工单处理 → 知识沉淀”** 的基础闭环，但需明确：

- `2026-08-21` 是计划发布时间，不是当前已上线或 UAT 通过的证据；上线验收前统一标记 `PLANNED`。
- “自动进入智能体知识”表示自动归属/挂载，不自动等于内容已完成解析、审核、索引并可被授权用户检索。
- “游离”不等于无租户、无权限或公开知识；必须保留租户归属、来源、权限和审计，并提供后续查看、关联智能体、撤回或归档入口。
- 标准一键上传不自动解决智能体主动发现候选、冲突去重、审核运营和效果回流等高级知识飞轮能力。

### 1.2 知识飞轮扩展需求

智能体详情已支持运营人员通过“新增知识”弹窗手工上传文件并发布。本需求在标准一键上传基线上继续定义两类智能化入口：

1. **用户自然语言驱动**：用户在会话中 @目标智能体，附加文件或引用当前会话/工单，并输入“上传知识并写入到智能体的 knowledge”等指令；智能体识别写知识意图，生成待确认的知识草稿。
2. **智能体内驱动**：智能体在服务过程中识别高频问题、已验证解决方案、低命中知识、重复工单或高质量处理总结，主动生成知识候选并邀请有权限的人审核。

三种入口（详情页手工新增、对话式新增、智能体内驱）必须复用同一条企业级 DC 治理链路，不能形成三套知识库或绕开权限、审核与审计。该能力属于知识飞轮实践：**知识消费 → 服务执行 → 结果验证/反馈 → 候选提炼 → 治理发布 → 再次消费 → 效果度量与持续优化**。

### 1.3 与最新 HelpDesk 交付计划的关系

- 员工 Skill 目标 8/14；处理人 Skill 目标 8/17。
- 处理人 Skill 的范围包含“生成知识产物”，但知识产物采用**定时触发、对话触发还是组合触发**尚未确认，不因 8/17 Skill 交付自动视为知识飞轮已打通。
- 知识产物卡是 11 类业务组件之一，负责展示、确认和反馈；它不能自行决定哪些工单可沉淀，也不能替代 DC 写入和真实回执。
- 工单草稿卡、附件确认卡和知识产物卡依赖会话附件能力：8/13 对齐方案/效果，8/14 为原计划发布日期；未取得发布记录和 UAT 前仍为外部依赖。
- 需要产品确认 eligible ticket：至少考虑已解决/已确认、处理结论完整、附件可用范围、PII/敏感信息、重复知识和人工确认。

## 2. 目标与非目标

### 2.1 目标

- 用户不离开当前处理流程即可把产物和附件一键上传为企业知识；存在智能体上下文时自动关联该智能体，无智能体时形成可治理的游离企业知识。
- 用户可进一步从文件、对话结论或工单解决方案生成受治理知识草稿/候选，并按策略关联智能体。
- 智能体可基于可解释规则主动发现知识候选，但默认不能无审核直接发布。
- 写入企业级 DC 后与租户、智能体、实例、来源、权限、版本和审核记录完整关联。
- 写入结果必须明确返回成功、处理中或失败；不得把“已生成草稿”表述为“已写入 DC”。
- 所有知识均可追溯、可更新、可撤回、可审计，并可用实际命中与解决反馈评估价值。

### 2.2 非目标

- 不把整段会话、处理人原话或附件未经处理直接发布为权威知识。
- 不允许普通用户绕过知识管理员将内容直接公开给全企业。
- 不以本地原型或 MCP Apps 卡片代替 DC 的持久化、索引和权限服务。
- 本期不解决 SharePoint 等外部数据源主动同步；该能力仍归属 DC 连接器（问题 #8c）。

## 3. 用户与权限

| 角色 | 可发起 | 可编辑草稿 | 可审核/发布 | 可撤回 | 默认范围 |
|---|---|---|---|---|---|
| 普通员工 | 对话提交文件/建议 | 仅本人草稿 | 否 | 本人未提交草稿 | 继承当前会话可见范围 |
| 工单处理人 | 工单转知识、对话提交 | 是 | 按授权 | 按授权 | 所属业务线/处理组 |
| 智能体 | 自动生成候选 | 仅生成结构化候选 | 默认否 | 否 | 继承来源与目标智能体 |
| 知识审核员 | 查看待审 | 是 | 是 | 是 | 授权知识域 |
| 智能体管理员 | 手工上传、配置策略 | 是 | 按策略 | 是 | 指定智能体/实例 |
| 租户管理员 | 配置全局策略 | 是 | 是 | 是 | 本租户 |

强制规则：调用方必须具备 `knowledge:create`；有关联智能体时还必须具备目标智能体贡献权限，发布还需 `knowledge:publish`。无智能体时只能写入当前租户允许的企业知识空间并标记 `unbound`，不得猜测或静默绑定智能体。跨租户禁止，跨智能体写入需显式确认；知识可见范围不得高于来源材料允许的范围。

## 4. 三类入口与关键交互

### 4.0 标准一键上传（计划 2026-08-21）

适用于 HelpDesk 已解决工单的处理产物和附件：

1. 用户显式点击“一键上传企业知识”，系统展示待上传产物/附件、来源工单、租户和归属预览。
2. 若当前流程携带有效智能体标识，自动关联该智能体；若没有智能体，创建 `unbound` 游离企业知识，不得猜测目标。
3. 服务端执行权限、文件安全、租户隔离和幂等检查，并返回结构化状态、知识标识、归属类型和审计标识。
4. 只有真实 DC 回执满足约定成功状态才能显示上传成功；超时、部分失败或归属不明时不得伪造成功。
5. 发布后还需验证解析、索引和授权检索。若回执仅表示“已接收/处理中”，页面必须展示对应中间态，而不是“已发布”。
6. 游离知识必须可在企业知识池查看，并支持有权限用户后续关联智能体、调整范围、撤回或归档。

### 4.1 智能体详情手工新增（现有能力保留）

运营人员在智能体详情点击“新增知识”，选择文件并保存发布。需补充统一的目标知识域、可见范围、重复检测、审核策略和来源标记 `manual_agent_detail`。

### 4.2 自然语言对话新增（新增）

典型指令：`@HelpDesk Assistant 上传知识并写入到智能体的 knowledge`，可附 `documents.zip`、PDF、DOCX、TXT、MD、YAML、HTML 或引用当前对话/工单。

交互步骤：

1. 识别 `knowledge.ingest` 意图，读取会话附件引用，不复制不可访问的文件。
2. 校验发起人身份、目标租户/智能体/实例、文件格式/大小/病毒、压缩包展开上限和目标贡献权限。
3. 若存在智能体上下文则展示并校验自动归属结果；若不存在则明确显示“将作为游离企业知识保存”。知识域、可见范围或更新策略不明确时必须追问；禁止猜测目标智能体。
4. 解析文件和会话，提取标题、摘要、问答/步骤、标签、来源引用及候选权限。
5. 展示“知识写入确认卡”：目标智能体、来源、文件列表、条目数、脱敏结果、相似知识、可见范围、审核策略和风险。
6. 用户明确确认后创建**知识草稿/审核任务**；默认不直接发布。
7. 审核通过后调用 DC 写入 API，返回 `knowledgeId`、`version`、`status`、目标、范围和审计号。
8. 失败时保留草稿，展示可操作原因与重试入口；部分文件失败不得宣称整批成功。

### 4.3 智能体内驱沉淀（新增）

候选触发信号至少包括：

- 相同/相似问题在 30 天内达到租户配置阈值；
- 工单已由用户确认解决，处理步骤完整且评分达到阈值；
- 知识检索无命中或低置信度，但人工处理形成稳定答案；
- 已有知识反复被反馈“未解决”，新方案经多次验证；
- 业务规则或标准操作在会话中被授权人员明确确认。

内驱流程只能自动生成候选并计算质量分，默认进入人工审核。仅当租户开启白名单、来源可信、无敏感信息、无冲突、质量分达标且权限范围明确时，才允许策略化自动发布；自动发布必须可回滚并通知知识管理员。

## 5. 统一状态机

标准一键上传基础状态：

`selected → validating → uploading → accepted/processing → indexed | upload_failed | partially_succeeded`

知识飞轮受治理状态：

`detected → validating → parsing → draft → conflict_check → pending_review → approved → writing → published`

异常/分支状态：`needs_clarification`、`rejected`、`write_failed`、`partially_succeeded`、`withdrawn`、`superseded`。

- `draft` 只代表内容已生成，不代表 DC 已写入。
- 只有 DC 返回明确 `published + knowledgeId + version` 才能向用户显示“知识已发布”。
- 超时或结果未知必须显示“状态待确认”，并通过幂等键查询，禁止重复创建。

## 6. 内容治理规则

1. **解析**：压缩包先列目录再展开；禁止可执行文件、路径穿越、嵌套压缩炸弹；单文件与总大小由租户策略限制。
2. **脱敏**：识别姓名、电话、邮箱、账号、密钥、Token、客户数据、日志中的身份信息；高风险内容阻断发布。
3. **事实与引用**：保留原文件、会话消息、工单及解决确认的不可变引用；生成内容需能回溯证据片段。
4. **冲突与去重**：按内容指纹保证请求幂等；按语义相似度识别已有知识，支持新建、合并、更新已有版本或放弃。
5. **质量**：至少校验准确性、完整性、可复用性、时效、可执行性、语言和适用范围。
6. **权限**：入库权限标签取“目标策略”与“来源 ACL”的更严格交集；检索必须按用户身份 pre-filter。
7. **生命周期**：支持草稿、审核、发布、过期复核、撤回、归档和版本回滚；来源失效时触发复核。
8. **人工可控**：展示模型提取结果与风险，不隐藏改写；发布前允许编辑，关键字段变化后旧确认失效。

## 8. 平台接口与职责边界

| 能力 | 责任方 | 最低要求 |
|---|---|---|
| 会话意图识别、追问、编排 | 灵基 Agent/Skill | 识别写知识意图，生成结构化参数，不越权执行 |
| 会话附件引用下传 | 灵基 Session / MCP Apps | 提供文件引用、元数据、访问令牌和生命周期，不把二进制塞入 LLM 文本 |
| 确认/审核卡 | MCP Apps | 展示草稿、风险和目标；收集显式确认；不自行持久化知识 |
| 标准一键上传入口与归属解析 | 灵基 / DC | 上传产物和附件；有智能体上下文自动关联，无智能体创建租户级 `unbound` 知识；返回真实状态 |
| 游离企业知识管理 | DC / Console | 查看、检索前治理、后续关联智能体、调整权限、撤回与归档 |
| 统一写入、解析、索引、版本 | 企业级 DC | 标准 API、幂等、异步任务、去重、版本、回滚、状态查询 |
| 身份与权限 | 灵基 IAM + DC | 调用权限、来源 ACL、目标范围及检索权限闭环 |
| 工单事实与反馈 | HelpDesk 后台 | 提供工单、解决确认、评分和来源引用，不直接绕过 DC 发布 |
| 审计与运营 | DC / Console | 全链路审计、待审列表、失败重试、撤回、指标报表 |

建议 Tool 契约：`Create_Knowledge_Ingestion`、`Parse_Knowledge_Source`、`Check_Knowledge_Conflict`、`Submit_Knowledge_Review`、`Publish_Knowledge`、`Get_Knowledge_Ingestion_Status`、`Withdraw_Knowledge`。

## 9. 验收场景

1. 选择处理产物和附件并一键上传：有智能体上下文时回执明确 `bindingType=agent` 及目标智能体；无智能体时回执明确 `bindingType=unbound`，且可在当前租户企业知识池查看。
2. 计划发布日期到达不自动视为完成；必须验证真实上传回执、解析/索引状态和授权检索。失败、超时、部分成功或归属不一致时不得显示完整成功。
3. 同一批产物/附件重复点击按幂等键复用请求，不产生重复知识；游离知识可由有权限用户后续关联智能体并留下审计记录。
4. 用户附加 `documents.zip` 并 @HelpDesk Assistant 下达写入指令，系统先展示文件和归属确认，不直接报成功。
5. 无智能体时不得因“未指定目标智能体”而阻断标准上传，但必须明确游离归属；显式要求写入某智能体而无权限、压缩包超限、含恶意文件或敏感信息时准确阻断并说明原因。
6. 引用当前工单时，草稿包含工单号、解决确认和证据引用，且移除个人信息。
7. 存在 90% 相似知识时展示对比，允许更新已有版本而不是重复创建。
8. 审核拒绝后保留原因；修改后可重新提交，审计链连续。
9. DC 写入成功返回知识编号、版本、归属和索引状态；失败或超时不展示成功，重试不产生重复知识。
10. 知识仅对授权部门可检索，其他用户无法通过关键词或向量检索越权获取。
11. 智能体内驱候选能解释触发原因、证据和质量分；未配置自动发布时不会自行发布。
12. 发布后的知识被引用回答，并将“已解决/未解决”、人工升级和评分回流到效果指标。
13. 知识撤回或来源失效后检索及时下线，历史版本和审计仍可追溯。

## 10. 指标

- 漏斗：候选数 → 草稿数 → 提审数 → 通过数 → 发布数。
- 效率：平均解析时长、平均审核时长、发布成功率、失败重试率。
- 质量：重复率、敏感信息拦截率、过期率、撤回率、审核通过率。
- 业务：知识命中率、自助解决率、转人工率、同类工单下降率、知识辅助解决时长。
- 内驱：候选采纳率、自动发布回滚率、候选到首次命中的周期。

指标必须按租户、智能体、知识域、来源和版本分层统计，不得仅统计“上传成功”。

## 11. 分阶段计划与依赖

### 标准能力：Foundation + DC 计划 2026-08-21 发布并进入验收

- 责任：Foundation + DC 由 @武晨曦、@陆阳推进标准能力；@邹茂桃负责 HelpDesk 场景、依赖协调与验收。
- 项目衔接：员工 Skill 目标 8/14；处理人 Skill 目标 8/17，包含知识产物入口但不代表完整知识飞轮已打通。
- 会话附件依赖：8/13 对齐方案/效果，8/14 为原计划发布日期；实际发布和 UAT 前保持外部依赖状态。
- 目标：产物/附件一键上传企业知识；有智能体自动归属，无智能体游离。
- 发布后验收：四条主路径、权限、真实回执、幂等、游离知识管理、解析/索引和授权检索。
- 状态：`PLANNED`；在发布记录和 UAT 证据齐备前不得写成“已上线/已解决”。

### Phase 0：高级飞轮契约与治理（与标准能力验收并行）

- 输出：自然语言/工单引用、候选生成、权限矩阵、审核策略、容量限制、效果回流和正式排期。

### Phase 1：对话式受控沉淀 MVP（DC API 就绪后 2～3 周）

- 支持文本/PDF/DOCX/MD 及会话/工单引用；ZIP 可先做受限预览后异步解析。
- 只支持“生成草稿 → 人工审核 → DC 发布”，不启用自动发布。
- 打通回执、失败重试、版本、来源追溯和基本权限。

### Phase 2：智能体内驱候选（Phase 1 后 2～4 周）

- 增加频次、解决确认、评分和低命中触发器；提供候选队列和质量分。
- 增加更新已有知识、过期复核、反馈回流及运营指标。

### Phase 3：策略化自动发布与企业连接器

- 仅对白名单知识域启用，配套回滚、抽检、告警和漂移监控。
- 与 SharePoint 等连接器统一进入 DC 治理，不另建旁路。

标准一键上传前置条件：8/21 能力实际发布、可用环境、权限/归属协议、真实状态回执、游离知识管理入口和索引/检索验证。高级飞轮另依赖会话附件引用下传、知识权限模型、审核工作台、智能体/实例稳定标识、审计、幂等和效果回流。任一关键依赖未就绪时，只能标记对应中间态或演示草稿/确认，不能宣称形成生产知识飞轮。
